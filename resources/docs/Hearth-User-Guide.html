Hearth Media · Installation, Configuration and Operations
01 · Overview

What Hearth does

Hearth is a self-hosted media server packaged as a Windows desktop application. It stores nothing on a third-party streaming service: your video, music and documents stay in the folders you choose, while the bundled server indexes them and makes them available through a browser-based streaming interface.

The desktop app is the control panel for the server. It handles first-time setup, scanning, users, network access, playback settings, diagnostics, backups and updates. The web app is what your household actually uses: a dark, poster-driven interface with Home, Movies, TV, Music, Files, Collections and Search. Both interfaces are served by the same bundled Node.js server and access the same database, so changes made in either place are reflected immediately.

Hearth deliberately separates two jobs. Metadata providers only supply descriptions, ratings and artwork; the playable files always come from your configured folders. This makes the system safe to use with personal media and easy to move: if you change PCs, you can point Hearth at the same folders, restore a database backup, and keep your watch history and permissions.

What is bundled

The installer includes the Electron desktop shell, a Node.js runtime for the server, SQLite, FFmpeg/ffprobe, hls.js, an optional cloudflared tunnel helper and a Windows service wrapper. You do not need to install Node.js, Python, a database or FFmpeg separately.

02 · Installation

Install on Windows

Hearth ships as a 64-bit NSIS installer for Windows 10 and Windows 11. Download Hearth-Setup-1.0.0-x64.exe, double-click it, choose an installation folder if you do not want the default, and follow the wizard. Setup creates Start Menu and Desktop shortcuts and registers an uninstaller in Windows Settings > Apps. It does not delete your media or your server database when uninstalled.

1
Run the installer

Launch Hearth-Setup-1.0.0-x64.exe and allow Windows to run the file. Because the community build is not code-signed, SmartScreen may ask for confirmation; choose More info and Run anyway if you trust the source.

2
Choose the install location

The default is %LOCALAPPDATA%\Programs\Hearth. Program files and media storage are intentionally separate; your movies and music should live wherever you already keep them.

3
Launch Hearth

Use the finish-page launch button, the Desktop shortcut, or the Start Menu entry. The app starts in the system tray after you close the window, so the server keeps running unless you quit it from the tray.

SmartScreen and antivirus. The installer is unsigned. SmartScreen warnings are expected for any unsigned executable. Use an SHA-256 checksum from the release page to confirm the file before running it. If you distribute Hearth privately, signing your builds removes the warning.

03 · First Run

Complete the setup wizard

The first launch opens a single guided setup screen. Add one or more media folders, create your administrator password, and press Create my server. Hearth applies safe defaults, starts the server and begins scanning immediately. Advanced settings are collapsed and optional.

Dependencies

Hearth verifies its server runtime, SQLite and FFmpeg. These are bundled, so no separate downloads are required. cloudflared is included but disabled until you enable remote access.

Media folders

Add folders such as D:\Media\Movies, D:\Media\TV Shows, D:\Media\Music and D:\Media\Downloads. Assign each to Movies, TV, Music or Files. Hearth never moves or edits source files.

Administrator account

Create a username and a password of at least 12 characters. This account can manage libraries, users, network settings and backups. Regular accounts are created later in Users.

Network

Choose a port (default 7341) and bind address. Use All interfaces to allow LAN devices, or Localhost only if you plan to access Hearth exclusively through a local proxy or VPN.

The final wizard step saves the configuration, starts the server and queues the first scan. The exact LAN address appears on the dashboard and in Network. Open that address in a browser on another device, sign in, and your library should begin appearing as files are indexed.

04 · Libraries

Organize media and metadata

Libraries map real folders to categories. During a scan, Hearth walks each folder, skips symlinks and hidden entries, reads file metadata with ffprobe, records size and modification time, and creates indexed titles. Files that disappear are marked missing rather than deleted, so watch history and collections survive a temporarily disconnected drive.

Movie and TV filenames are parsed automatically. Names like Example Movie (2020).mkv and Show Name S01E02.mp4 produce sensible titles, years, seasons and episodes. Music is interpreted using Artist/Album/01 Track.mp3 folder layouts. You can also add sidecar posters, backdrops and subtitles next to your media, and Hearth will use them without any external API.

Movie (2010).mkv

Parsed as a movie title and release year. ffprobe supplies codecs, duration and available streams.

Show S01E02.mkv

Linked to a show, season 1 and episode 2. Descriptions are fetched when a TMDB key is configured.

Artist/Album/01 Song.flac

Grouped into artist and album views with track numbers preserved.

poster.jpg / fanart.jpg

Used directly as local poster and backdrop artwork, with no external provider required.

Episode.srt/.ass/.vtt

Offered as a selectable subtitle track and converted to WebVTT for browser rendering.

For richer movie and TV data, add a free TMDB API key in Metadata. For music, Hearth queries MusicBrainz without requiring a key, and an optional MusicBrainz token is supported. Responses and artwork are cached in the server database and artwork folder so repeated scans do not spam providers. If a match is wrong, use the manual identify controls to search again or edit the title, overview and year.

Scan control. Use Scan for an incremental scan, Full scan to re-probe every file, or Scan libraries to scan every enabled library. Startup scanning can be enabled in Playback. Progress, added titles and errors are shown on the dashboard.

05 · Web Interface

Browse and watch your library

The web app opens with a cinematic hero, Continue Watching, Recently Added, Trending and Recommended rows. Poster cards show rating and progress; hover reveals a quick play control. The sidebar and top navigation expose dedicated sections for Movies, TV Shows, Music, Files, Collections and Search, and the layout collapses cleanly on phones and tablets.

Movie pages include overview, rating, runtime, cast, codecs and download actions. Series pages group seasons and episodes. Music has artist and album browsing plus per-track playback. Files & Downloads provides folder navigation, size and date information, previews and downloads. Collections let each user group titles; Favorites and Watchlist are personal and do not affect other profiles.

Playback controls

The player supports play/pause, seek, 10-second skips, volume, speed from 0.5× to 2×, fullscreen, Picture-in-Picture, audio track selection, subtitle selection, resume and automatic next-episode playback. Keyboard shortcuts include Space/K for play, J/L or arrow keys for seeking, M for mute and F for fullscreen.

When a browser can decode the file, Hearth uses Direct Play and serves bytes directly with HTTP Range support. When the container or codec is incompatible, it creates an authenticated HLS session and FFmpeg produces 4-second segments. The player adapts among source, 1080p, 720p, 480p and 360p renditions depending on the title and browser, and server settings control hardware acceleration and concurrent transcodes.

06 · Users

Accounts and permissions

Every viewer should have their own account. Profiles keep separate Continue Watching positions, favorites, watchlists, collections and playback preferences. Administrators manage users from the desktop control panel and can create or edit accounts, reset passwords, revoke sessions, disable accounts, allow or block downloads, and restrict access to specific libraries.

A restricted user with access to Movies and Files will not see TV or Music libraries, titles, artwork or download links from the excluded libraries. Downloads and previews are separate from browsing, so you can let someone browse a folder without letting them download its contents. Passwords are stored using salted scrypt hashes, and browser sessions use HttpOnly cookies with CSRF protection.

Good household setup

Create one admin account for yourself, one normal account per household member, and disable downloads on accounts used by children or guest devices. Revoke sessions after changing a password or removing access to a library.

07 · Files

Sharing documents and downloads

A library of type Files is a controlled file distribution area rather than a streaming library. It can contain documents, archives, images, installers or any other content. Users with permission can browse folders, see sizes and modification dates, preview supported files, download single files, and download folders as ZIP archives.

Single-file downloads support HTTP Range requests, so interrupted downloads can resume. Folder downloads are streamed as a ZIP archive rather than being loaded into memory, which makes them practical even for large folders. Path validation prevents access above the configured root, and symbolic links are skipped during scanning and ZIP creation.

Previews

Images, PDFs, text files, videos and audio files can be previewed inline. Office documents and unsupported formats show file information and can still be downloaded. Text preview is limited to 1 MB, and media preview is limited to 2 GB per file.

08 · Network

LAN and remote access

For household use, bind Hearth to all interfaces and open the displayed http://your-pc-ip:7341 address on another device. The dashboard lists detected adapters and port. Windows may ask for firewall permission the first time a remote device connects.

For access away from home, Hearth offers several modes with different trade-offs. The most private permanent option is a VPN such as Tailscale or WireGuard: install the VPN client, enable VPN mode, and Hearth uses the encrypted VPN address. A reverse proxy such as Caddy or Nginx can provide a permanent HTTPS domain. A temporary Cloudflare quick tunnel can be started in one click for testing; the URL is HTTPS and still requires sign-in, but it changes after restarts and is not intended as a permanent address.

Off / LAN only

Best for: household streaming.
Security: no internet exposure, and all routes still require accounts.

VPN

Best for: private permanent remote use.
Security: traffic travels through your VPN with no public port forwarding.

HTTPS reverse proxy

Best for: a permanent domain.
Security: terminate TLS at Caddy/Nginx and keep Hearth bound to a private interface.

Quick tunnel

Best for: temporary test access.
Security: HTTPS and authenticated, but the URL is ephemeral.

Never expose an unauthenticated server. Hearth requires sign-in for all media, file and administrative routes. If you use a proxy, keep its own access controls enabled and do not bypass authentication.

09 · Service

Run Hearth in the background

By default, closing the Hearth window minimizes it to the system tray and the server continues running. Quitting from the tray stops the desktop-managed server. If you want the server to survive reboots even when the desktop app is not running, install the optional Windows service from the dashboard.

The service uses a wrapper around the same Hearth runtime and writes rolling logs to your server data folder. Windows will request administrator approval to install, start, stop or uninstall it. When the service is running, the control panel automatically administers the service instead of launching a second process, avoiding port conflicts. Stop the service before changing the port or restoring a backup.

Restart on failure

The desktop-managed process can automatically restart after an unexpected exit, with increasing delay. The Windows service has its own failure-restart policy. You can toggle desktop automatic restart from the dashboard service panel.

10 · Backup

Protect settings and history

Backups contain a consistent SQLite snapshot of libraries, users, permissions, watch history, collections and encrypted settings. Original media files and artwork caches are not duplicated, which keeps backups small. Create a backup before updating Hearth or moving libraries, then download it to another drive.

To restore, stop the server or service, choose a .hearthbackup file, and Hearth keeps a pre-restore snapshot before replacing the live database. Because API keys are encrypted, a backup restores cleanly on the same installation; when migrating to another machine, re-enter provider keys after restoring. Test restores occasionally rather than discovering a problem during an emergency.

11 · Updates

Check and install updates

The Updates section checks an HTTPS update manifest and downloads a verified installer. A manifest entry includes the version, download URL and SHA-256 checksum. Hearth refuses non-HTTPS sources and rejects packages whose checksum does not match. Once downloaded and verified, it launches the installer in silent mode.

{
  "version": "1.1.0",
  "url": "https://example.com/downloads/Hearth-Setup-1.1.0-x64.exe",
  "sha256": "64 hexadecimal characters",
  "notes": "Improved subtitle selection and scan performance"
}

Until you publish an update feed, the section reports that you are up to date. You can also install a newer installer manually; settings and libraries are preserved because they live outside the program folder.

12 · Troubleshooting

Diagnostics and common fixes

Use the dashboard activity feed and Logs for the fastest diagnosis. Logs are structured JSON and rotate daily. The diagnostics panel shows the Node version, FFmpeg version, validated hardware encoders, database location and remote access state. If a scan fails, the affected path and reason are recorded rather than silently skipped.

Device cannot open the web app

Confirm both devices are on the same network, use the adapter IP shown in Network, and check Windows Firewall.

Library is empty

Verify the library type matches the files, run a full scan, and check that files are not hidden or symlinked.

Playback buffers

Try a lower rendition, allow hardware transcoding, or confirm the storage disk is not saturated.

Subtitles do not appear

Image-based PGS/DVD subtitles cannot be converted to browser text; use an SRT/ASS/VTT sidecar.

Remote test fails

Confirm the tunnel/proxy is running and its URL reaches this server; check HTTPS certificates and firewall rules.

Missing files warning

Reconnect the drive, correct the library folder, then scan again. Missing titles remain in history.

If the desktop app cannot reach a running service, stop the service, open Hearth again, and verify the port in Network. If a restore fails, do not overwrite the pre-restore snapshot; check disk space and confirm the backup file is a Hearth-generated .hearthbackup file.

Practical operating notes

Keep your media on reliable storage, create a backup after major library changes, and give each viewer their own profile. Use VPN or HTTPS reverse-proxy mode for permanent remote access and reserve quick tunnels for temporary testing. The result is a private, fast streaming platform that remains entirely under your control.
